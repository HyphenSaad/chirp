# Support

Thanks for using Chirp! Here are the ways to get help.

## Documentation first

Before opening an issue, please check:

- 📖 [Quick Start](docs/QUICKSTART.md) — 5-minute tour
- 📚 [API Reference](docs/API_REFERENCE.md) — every class and method
- 💡 [Examples](docs/EXAMPLES.md) — before/after comparisons
- ❓ [FAQ](docs/FAQ.md) — common questions
- 🔧 [Troubleshooting](docs/TROUBLESHOOTING.md) — when things go wrong

## Ask a question

For **how-to questions**, **usage help**, or **design discussions**:

👉 [Open a Discussion](https://github.com/hyphensaad/chirp/discussions)

Discussions are better than Issues for questions because:

- The community can help faster
- Answers are searchable for future users
- No noise in the issue tracker for bug reports

## Report a bug

Found a bug? Open an issue:

👉 [New Bug Report](https://github.com/hyphensaad/chirp/issues/new?template=bug_report.md)

Please include:

- Chirp version
- Java version
- Operating system
- Minimal reproducible example
- Expected vs actual behaviour

## Request a feature

Have an idea for a new feature?

👉 [New Feature Request](https://github.com/hyphensaad/chirp/issues/new?template=feature_request.md)

Features are evaluated against the project's scope (see
[CONTRIBUTING.md](CONTRIBUTING.md#before-you-contribute)).

## Report a security vulnerability

**Do not open a public issue.** See [SECURITY.md](SECURITY.md).

## Commercial support

Chirp is maintained as an open-source project. There is no commercial
support offering at this time.

## Response times

| Channel         | Expected response     |
| --------------- | --------------------- |
| Bug report      | 3–7 business days     |
| Feature request | 7–14 business days    |
| Discussion      | Often within 48 hours |
| Security report | 72 hours              |

## Community guidelines

All interactions are governed by our
[Code of Conduct](CODE_OF_CONDUCT.md). Please be kind and constructive.
